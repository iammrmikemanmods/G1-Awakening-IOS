# Build017 memory ZIP policy

Preserve repository paths, source commit identity and prior Build016 IPA/source.
Do not overwrite user saves, original resource archives or playable map grids.
Every export must reject traversal, duplicate paths, CRC errors and missing
manifest members, and include SHA-256 evidence and this policy under the name
README_MEMORY_ZIP_POLICY.md at its root.

Source checkpoints contain the exact compiled Git source and separately labelled
export evidence, not original game assets, private credentials, raw mesh dumps,
fonts, build caches or the offline derived owner texture pack. Visual review
ZIPs contain labelled rendered comparisons/video and documentation, not the
private extraction inputs. CPU previews are not iPhone screenshots.

A complete owner-data IPA may include CleanTextures017/*.png and its manifest,
derived solely from the user's source archive. Preserve all old game, cinematic,
icon and licence members byte-for-byte. Change only the reviewed executable,
compiled Info.plist, root policy and added reconstructed-texture pack. Validate
every added pack member against its output hash and native source-pixel key.
Original iphone.big SHA-256 is
663d2888982093ce66b7811ccb7a6ad3acd37fc02ffa85144775b88c39e83cb4.

Authored joint/assembly motion is an approximation, not recovered original
animation. Do not mark unsupported forms or support sequences as finished 3D.
The compiled deployment minimum stays iOS15.0 on arm64 iPhone/iPad. No older
OS/hardware claim is established. AppSync ad-hoc signing is not developer
provisioning or App Store approval. A candidate remains untrusted for physical
visual fidelity until hardware evidence exists.

Freeze completed artifacts immutably; corrected exports require new names,
checksums and validation records. Keep prior failed build logs as failure
history, but do not distribute a failed executable as a usable candidate.
